# 인증 + 겸상 열기 + 목록 화면 설계

담당: wgmin0416. 요구사항은 `docs/features/meal/requirements.md`, 공통 표현은 `docs/common/design-system.md`를 따른다.

### SCR-MEAL-LOGIN 로그인
- 경로: `/login`
- 관련 요구사항: REQ-MEAL-01
- 진입: 로그인하지 않은 사용자가 로그인이 필요한 화면에 들어오면 이 화면으로 이동한다. 원래 가려던 화면을 기억한다.
- 구성: 카드 하나에 화면 제목 "겸상 로그인"과 단계별 입력
- 1단계 이메일 입력
  - 안내 문구: 사내 이메일로 인증 코드를 보낸다는 안내
  - 이메일 입력창과 "인증 코드 받기" 버튼
  - 이메일이 비어 있거나 발송에 실패하면 이메일 입력창 아래에 안내
- 2단계 코드 입력
  - 안내 문구: 코드를 보낸 이메일 주소 표시
  - "인증 코드" 라벨과 6칸 숫자 입력. 각 칸의 접근성 이름은 "인증 코드"
  - 제출: 6칸을 모두 채우는 순간 자동 제출한다. "로그인" 버튼으로도 제출할 수 있다 (자동 제출이 실패한 뒤 다시 제출하는 경우 등)
  - 6자리가 안 되면 제출하지 않고 안내. 코드가 틀렸거나 만료되면 코드 입력 아래에 안내하고 2단계에 머문다
  - "이메일 다시 입력" 버튼(보조 행동)을 누르면 1단계로 돌아간다
- 완료: 로그인되면 기억한 화면으로, 없으면 `/`로 이동한다

### SCR-MEAL-LIST 겸상 목록
- 경로: `/` (로그인 필요)
- 관련 요구사항: REQ-MEAL-04, REQ-MEAL-10
- 진입: 로그인 후 첫 화면. 로그인 화면에서 돌아갈 화면이 없으면 이 화면으로 온다.
- 구성: 화면 제목 "겸상 목록"과 제목 오른쪽의 "겸상 열기" 버튼(핵심 행동), 그 아래 탭 두 개 "모집중인 겸상" / "내 겸상"과 선택한 탭의 겸상 카드 목록
  - "겸상 열기" 버튼을 누르면 겸상 열기 화면(`/meals/new`)으로 이동한다
- 탭
  - 처음 들어오면 "모집중인 겸상" 탭을 보여준다
  - 선택한 탭은 주소에 남긴다(`/?tab=mine`). 상세에서 뒤로 가기로 돌아오면 보던 탭이 유지된다
  - 탭 높이는 터치 영역 최소 44px (`docs/common/design-system.md` §5)
- 카드 전체를 누르면 해당 겸상 상세(`/meals/:id`)로 이동한다
- 내 겸상 (REQ-MEAL-10)
  - 대상: 내가 Host이거나 참여 중인 겸상. 상태와 관계없이 표시하고, 정산·취소 겸상은 주문 예정 시간이 최근 7일 이내인 것만. 조회 기준은 `docs/common/db-schema.md` §9 내 겸상
  - 정렬: 진행 중(모집중·주문중·주문완료)을 먼저 주문 예정 시간이 가까운 순, 그 아래 끝난 겸상(정산·취소)을 주문 예정 시간 최근 순
  - 카드: 제목(두 줄까지), 유형 배지(식사/배달), 상태 배지(모집중·주문중·주문완료·정산·취소), 주문 예정 시간(예: `10월 27일 (화) 오후 12:30`)
  - 끝난 겸상도 카드 모양은 같고 상태 배지 문구로 구분한다
  - 빈 목록: "참여 중인 겸상이 없습니다."
- 모집중인 겸상 (REQ-MEAL-04)
  - 대상: 상태가 모집중이고 주문 예정 시간이 지나지 않은 겸상. 최신순(생성 시각 내림차순)
  - 내가 참여한 모집중 겸상도 이 목록에 함께 표시한다
  - 카드: 제목(두 줄까지), 유형 배지(식사/배달), 현재 인원/정원(예: `2/4명`)
  - 빈 목록: "모집중인 겸상이 없습니다."
- 상태 표현 (탭마다 따로)
  - 불러오는 중: 탭 안에 로딩 표시
  - 실패: 탭 안에 실패 안내. 한 탭이 실패해도 다른 탭은 표시한다

### SCR-MEAL-CREATE 겸상 열기
- 경로: `/meals/new` (로그인 필요)
- 관련 요구사항: REQ-MEAL-03
- 진입: 목록 화면(SCR-MEAL-LIST)의 "겸상 열기" 버튼
- 구성: 카드 하나에 화면 제목 "겸상 열기"와 입력 폼, 제출 버튼 "겸상 열기". 폼 너비는 `docs/common/design-system.md` §4 입력 폼 너비를 따른다
- 입력 항목 (순서대로). 필수 항목은 라벨에 필수 표시(*), 선택 항목은 라벨에 "(선택)"을 붙인다
  - 제목 (필수): 한 줄 입력
  - 유형 (필수): 식사 / 배달 중 하나 선택. 기본 선택 없음
  - 식당/가게명 (필수): 한 줄 입력
  - 가게 메뉴판 링크 (선택): 한 줄 입력. http:// 또는 https:// 주소만 받는다
  - 집합/수령 장소 (필수): 한 줄 입력
  - 주문 예정 시간 (필수): 날짜와 시각 입력. 현재 이후 시각만 받는다. 설명 문구 "이 시각이 되면 참여·메뉴 변경이 잠깁니다."
  - 정원 (필수): 1 이상의 정수. 설명 문구 "Host 본인을 포함한 최대 인원입니다."
  - 메모 (선택): 여러 줄 입력
- 입력 오류: 제출 시 검사하고, 오류가 있으면 생성하지 않고 해당 입력창 아래에 안내한다
  - 필수 항목이 비어 있음, 주문 예정 시간이 현재 이후가 아님, 메뉴판 링크가 http(s) 주소가 아님, 정원이 1 이상의 정수가 아님
- 제출 중: 버튼에 로딩 표시, 입력 비활성
- 요청 실패: 제출 버튼 위에 실패 안내. 입력값은 유지한다
- 완료: 새 겸상 상세(`/meals/:id`)로 이동한다. 뒤로 가기로 이 화면에 돌아오지 않는다

### SCR-MEAL-INFO 겸상 상세의 겸상 정보
- 위치: 겸상 상세(`/meals/:id`, 로그인 필요)의 meal 섹션. 상세 화면의 다른 섹션(참여·공지·정산)은 각 기능 문서를 따른다
- 관련 요구사항: REQ-MEAL-03, Host 관리 동작 REQ-MEAL-05~07, Host 넘기기 응답 REQ-MEAL-08~09
- 구성: 카드 하나
  - 유형 배지(식사/배달), 상태 배지(모집중·주문중·주문완료·정산·취소. `docs/common/domain.md` 상태)
  - 제목
  - 식당/가게명 (값이 있을 때만)
  - 집합/수령 장소: 항상 표시. 모양과 수정 동작은 `docs/features/notice/screen.md` SCR-NOTICE-03을 따른다 (REQ-NOTICE-02)
  - "가게 메뉴판 보기" 링크 (값이 있을 때만). 새 탭에서 외부 메뉴판을 연다
  - 주문 예정 시간. 예: `10월 27일 (화) 오후 12:30`
  - 현재 인원/정원. 예: `인원 2/4명`
  - 메모 (값이 있을 때만, 줄바꿈 유지)
- 취소된 겸상: 상태 배지 "취소" 아래에 "취소 사유: (사유)"를 표시한다 (Host가 즉시 취소한 경우만 사유가 있음)
  - Host 넘기기 실패로 취소된 겸상은 참여자에게 "Host 넘기기가 수락되지 않아 취소되었습니다."를 표시한다
- Host 관리 동작: Host이고 겸상이 열려 있을 때(모집중이고 주문 예정 시간 전) 카드 아래에 표시한다. Host가 아니면 표시하지 않는다
  - 상세를 보는 중에 주문 예정 시간이 되면 새로 고침 없이 Host 관리 동작을 숨긴다
  - "주문 예정 시간 수정" 버튼(보조 행동) → 주문 예정 시간 수정 대화상자(SCR-MEAL-ORDER-TIME)
  - "Host 넘기기" 버튼(보조 행동) → Host 넘기기 대화상자(SCR-MEAL-HANDOVER)
    - Host 외 참여자가 없으면 비활성. 아래에 "다른 참여자가 없으면 Host를 넘길 수 없습니다. 겸상 취소를 이용해 주세요."
  - "겸상 취소" 버튼(위험 행동. 빨간 외곽선) → 겸상 취소 대화상자(SCR-MEAL-CANCEL)
- Host 넘기기 대기 중 (Host에게)
  - 카드 아래 안내 상자: "Host 넘기기 대기 중", 사유, "거절 n명 / 대상 m명"
  - "주문 예정 시간 수정"은 비활성. 아래에 "Host 넘기기 대기 중에는 주문 예정 시간을 수정할 수 없습니다."
  - "Host 넘기기" 버튼은 숨긴다. "겸상 취소"는 그대로 쓸 수 있고, 취소하면 대기 중인 요청도 함께 닫힌다
- Host 넘기기 정보를 불러오지 못한 경우 (Host에게): 실패 안내를 보이고, 마지막으로 확인한 대기 상태를 유지한다. 한 번도 확인하지 못했으면 대기 여부에 따라 달라지는 "주문 예정 시간 수정"은 비활성, "Host 넘기기"는 숨긴다. "겸상 취소"는 그대로 쓸 수 있다
- Host 넘기기 요청·거절·수락은 상대 화면에 새로 고침 없이 반영한다(결정 #81, `docs/common/db-schema.md` §10). 참여자 화면의 응답 상자, Host 화면의 거절 수가 바로 갱신된다
- Host 넘기기 대기 중 (Host가 아닌 참여자에게. SCR-MEAL-HANDOVER-RESPONSE)
  - 카드 아래 응답 상자: 제목 "Host 넘기기 요청", 사유, 안내 "수락하면 이 겸상의 Host가 됩니다. 주문 예정 시간까지 아무도 수락하지 않거나 모두 거절하면 겸상이 취소됩니다."
  - "수락"(주요), "거절"(보조) 버튼
  - 수락: 확인 대화상자("Host를 넘겨받을까요?", "돌아가기"·"수락") 후 처리. 성공하면 다시 불러와 Host 관리 동작이 보인다
  - 거절: 확인 없이 바로 처리. 성공하면 버튼 대신 "거절했습니다."를 보인다. 거절한 뒤에는 수락할 수 없다
  - 실패 안내 (응답 상자 안)
    - 이미 처리됨(`handover_not_pending`): "이미 처리된 요청입니다. 새로 고침해 주세요."
    - 주문 예정 시간 지남(`handover_expired`): "주문 예정 시간이 지나 수락할 수 없습니다."
    - 참여자가 아님(`not_member`): "참여자만 응답할 수 있습니다."
    - 위 세 경우는 응답 버튼을 숨긴다. 그 밖의 실패는 버튼을 유지해 다시 시도할 수 있다
  - 상세를 보는 중에 주문 예정 시간이 되면 응답 상자의 버튼을 숨긴다
- 참여자가 아닌 사용자에게는 Host 넘기기 요청을 표시하지 않는다
- 상태 표현
  - 불러오는 중: 로딩 표시
  - 실패: 섹션 자리에 실패 안내
  - 없는 겸상: "겸상을 찾을 수 없습니다."

### SCR-MEAL-HANDOVER Host 넘기기 대화상자
- 위치: 겸상 상세 위에 겹쳐 열리는 대화상자. 별도 경로는 없다
- 관련 요구사항: REQ-MEAL-05
- 진입: SCR-MEAL-INFO의 "Host 넘기기" 버튼
- 구성
  - 제목 "Host 넘기기"
  - 안내 문구 "참여자 한 명이 수락하면 Host가 바뀌고, 내 참여와 메뉴는 삭제됩니다. 주문 예정 시간까지 아무도 수락하지 않거나 모두 거절하면 겸상이 취소됩니다."
  - 라벨 "넘기는 사유" 필수 여러 줄 입력. 예시 문구 "메뉴 변경 등". 열리면 입력창에 포커스
  - "돌아가기"(보조), "넘기기 요청"(주요) 버튼을 오른쪽 정렬
- 동작
  - 사유가 비었거나 공백만 있으면 요청하지 않고 입력창 아래에 "넘기는 사유를 입력해 주세요."
  - 처리 중: "넘기기 요청" 버튼에 로딩 표시, 입력 비활성
  - 성공: 대화상자를 닫고 다시 불러와 대기 중 안내 상자를 보인다
  - 실패: 입력 내용을 유지하고 입력창 아래에 안내
    - 다른 참여자 없음(`no_other_members`): "다른 참여자가 없으면 Host를 넘길 수 없습니다. 겸상 취소를 이용해 주세요."
    - 이미 대기 중(`handover_pending`): "이미 Host 넘기기를 요청했습니다."
    - 이미 열려 있지 않음(`meal_not_recruiting`): "모집중일 때만 Host를 넘길 수 있습니다."
    - Host가 아님(`not_host`): "Host만 Host를 넘길 수 있습니다."
  - 대화상자가 열린 채 주문 예정 시간이 되면: 입력 내용을 유지하고 "넘기기 요청" 버튼을 비활성으로 바꾸며 입력창 아래에 "모집중일 때만 Host를 넘길 수 있습니다."
  - 돌아가기, 바깥 누르기, Esc: 입력 내용을 버리고 닫는다

### SCR-MEAL-CANCEL 겸상 취소 대화상자
- 위치: 겸상 상세 위에 겹쳐 열리는 대화상자. 별도 경로는 없다
- 관련 요구사항: REQ-MEAL-06
- 진입: SCR-MEAL-INFO의 "겸상 취소" 버튼
- 구성
  - 제목 "겸상 취소"
  - 안내 문구 "취소하면 되돌릴 수 없고, 겸상이 목록에서 사라집니다."
  - 라벨 "취소 사유" 필수 여러 줄 입력. 열리면 입력창에 포커스
  - "돌아가기"(보조), "겸상 취소"(위험 행동. 빨간 채움) 버튼을 오른쪽 정렬
- 동작
  - 사유가 비었거나 공백만 있으면 취소하지 않고 입력창 아래에 "취소 사유를 입력해 주세요."
  - 처리 중: "겸상 취소" 버튼에 로딩 표시, 입력 비활성
  - 성공: 대화상자를 닫고 상세에 머문다. 상태 배지가 "취소"로 바뀌고 취소 사유가 보이며 Host 관리 동작이 사라진다
  - 대화상자가 열린 채 주문 예정 시간이 되면: 입력 내용을 유지하고 "겸상 취소" 버튼을 비활성으로 바꾸며 입력창 아래에 "모집중일 때만 겸상을 취소할 수 있습니다."
  - 실패: 입력 내용을 유지하고 입력창 아래에 안내
    - 이미 열려 있지 않음(`meal_not_recruiting`): "모집중일 때만 겸상을 취소할 수 있습니다."
    - Host가 아님(`not_host`): "Host만 겸상을 취소할 수 있습니다."
  - 돌아가기, 바깥 누르기, Esc: 입력 내용을 버리고 닫는다

### SCR-MEAL-ORDER-TIME 주문 예정 시간 수정 대화상자
- 위치: 겸상 상세 위에 겹쳐 열리는 대화상자. 별도 경로는 없다
- 관련 요구사항: REQ-MEAL-07
- 진입: SCR-MEAL-INFO의 "주문 예정 시간 수정" 버튼
- 구성
  - 제목 "주문 예정 시간 수정"
  - 라벨 "주문 예정 시간" 필수 날짜·시각 입력. 현재 주문 예정 시간이 채워져 있고, 열리면 입력창에 포커스. 설명 문구 "이 시각이 되면 참여·메뉴 변경이 잠깁니다."
  - "돌아가기"(보조), "저장"(주요) 버튼을 오른쪽 정렬
- 동작
  - 비었거나 현재 이후 시각이 아니면 저장하지 않고 입력창 아래에 "현재 이후 시각을 입력해 주세요."
  - 처리 중: "저장" 버튼에 로딩 표시, 입력 비활성
  - 성공: 대화상자를 닫고 겸상 정보에 바뀐 주문 예정 시간이 보인다
  - 대화상자가 열린 채 주문 예정 시간이 되면: 입력 내용을 유지하고 "저장" 버튼을 비활성으로 바꾸며 입력창 아래에 "모집중일 때만 주문 예정 시간을 수정할 수 있습니다."
  - 실패: 입력 내용을 유지하고 입력창 아래에 안내
    - Host 넘기기 대기 중(`handover_pending`): "Host 넘기기 대기 중에는 주문 예정 시간을 수정할 수 없습니다."
    - 이미 열려 있지 않음(`meal_not_recruiting`): "모집중일 때만 주문 예정 시간을 수정할 수 있습니다."
    - 현재 이후가 아님(`invalid_order_time`): "현재 이후 시각을 입력해 주세요."
    - Host가 아님(`not_host`): "Host만 주문 예정 시간을 수정할 수 있습니다."
  - 돌아가기, 바깥 누르기, Esc: 입력 내용을 버리고 닫는다
- Host 넘기기 대기 중에는 진입 버튼을 비활성으로 보인다(SCR-MEAL-INFO). 대화상자가 열려 있는 동안 대기가 시작된 경우는 저장 시 안내로 막는다
