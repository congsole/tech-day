# 공지 화면 설계

담당: congsole (통합·스키마). 요구사항은 `docs/features/notice/requirements.md`, 공통 표현은 `docs/common/design-system.md`를 따른다.

### SCR-NOTICE-01 공지 띠
- 경로: `/meals/:id` 겸상 상세의 맨 위 (로그인 필요)
- 관련 요구사항: REQ-NOTICE-01
- 표시 대상: 그 겸상의 Host와 참여자. 참여자가 아니면 띠를 표시하지 않는다
- 구성
  - 공지가 있을 때: `공지` + 공지 개수 + 최신 공지 내용 한 줄. 한 줄을 넘으면 말줄임
  - 공지가 없을 때: `공지` + `아직 올라온 공지가 없습니다`
  - 띠 전체가 하나의 버튼이며 터치 영역은 44px 이상이다
  - 읽음 여부는 표시하지 않는다 (읽음 기록이 없음)
- 동작: 띠를 누르면 공지 패널(SCR-NOTICE-02)이 열린다
- 상태 표현
  - 불러오는 중: 참여 여부를 아직 모르므로 띠를 표시하지 않는다
  - 참여 여부 확인 실패: 띠를 표시하지 않는다
  - 공지 조회 실패(참여자로 확인된 뒤): 띠 자리에 실패 안내

### SCR-NOTICE-02 공지 패널
- 경로: 겸상 상세 위에 겹쳐 열린다. 별도 경로는 없다
- 관련 요구사항: REQ-NOTICE-01
- 진입: 공지 띠(SCR-NOTICE-01)를 누른다
- 열리는 방식
  - 48em 미만: 아래에서 올라오는 시트. 화면 높이의 80%
  - 48em 이상: 오른쪽 패널. 너비 400px
  - 닫기 버튼, 패널 바깥 누르기, Esc로 닫는다
- 구성 (위에서 아래 순서)
  1. 머리: 제목 `공지`, 공지 개수(공지가 있을 때만), 닫기 버튼. Host에게만 `공지 쓰기` 버튼
  2. 작성 영역: Host가 `공지 쓰기`를 눌렀을 때만 보인다
     - 라벨 `공지 내용`, 예시 문구 `배달 위치, 배달 완료, 변경 사항 등`인 여러 줄 입력창. 열리면 입력창에 포커스
     - `취소`(보조), `게시`(주요) 버튼을 오른쪽 정렬
  3. 공지 목록: 최신순. 공지마다 작성 시각(보조 설명 크기)과 내용(줄바꿈 유지). 공지 사이는 구분선으로 나누고 테두리 상자는 쓰지 않는다
     - 작성 시각 형식: `10월 26일 오후 3:20`
- 동작
  - 게시: 내용이 비었거나 공백만 있으면 등록하지 않고 입력창 아래에 `공지 내용을 입력하세요.`
  - 게시 성공: 작성 영역을 닫고 목록 맨 위에 새 공지가 보인다. 공지 띠도 새 공지로 바뀐다
  - 게시 실패: 입력 내용을 유지하고 입력창 아래에 실패 안내
  - 취소: 입력 내용을 버리고 작성 영역을 닫는다
  - 공지는 수정·삭제하지 않는다. 잘못 올린 공지는 정정 공지를 새로 올린다
- 상태 표현
  - 빈 목록: `아직 올라온 공지가 없습니다.`

### SCR-NOTICE-03 집합/수령 장소
- 경로: `/meals/:id` 겸상 상세의 겸상 정보 안 한 항목 (로그인 필요)
- 관련 요구사항: REQ-NOTICE-02
- 위치: [확인 필요: 겸상 상세 화면 설계에서 겸상 정보 안의 위치 결정]. 이 문서는 장소 항목의 모양과 동작만 정한다
- 표시 대상: 겸상 상세를 보는 누구나
- 구성
  - 라벨: 유형이 식사면 `집합 장소`, 배달이면 `수령 장소`
  - 장소 내용
  - Host이고 겸상이 모집중이면 `수정` 버튼(보조)
- 동작
  - `수정`을 누르면 장소 내용 자리가 같은 라벨의 한 줄 입력창으로 바뀌고 현재 장소가 채워진다. 입력창에 포커스
  - `취소`(보조), `저장`(주요) 버튼을 오른쪽 정렬
  - 저장: 비었거나 공백만 있으면 저장하지 않고 입력창 아래에 `장소를 입력하세요.`
  - 저장 성공: 입력창을 닫고 바뀐 장소를 표시한다
  - 저장 실패: 입력 내용을 유지하고 입력창 아래에 안내. 모집중이 아니게 되어 막힌 경우 `모집중일 때만 장소를 수정할 수 있습니다.`
  - 취소: 입력 내용을 버리고 원래 표시로 돌아간다
