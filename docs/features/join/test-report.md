## 4. 실행 및 결과 기록 방법

- 구현한 요구사항부터 확인하고 통과·실패·미실시를 개별 기록한다.
- 실제 실행 시 검증 커밋, 환경, 날짜, 사용한 역할과 데이터 조건, 관찰 결과를 추가한다. 인증 정보와 실제 이메일 등 민감한 값은 기록하지 않는다.
- 준비된 데이터나 모의 응답으로 확인한 결과는 실제 DB·RLS·동시성 검증과 구분한다.
- 동시 참여·RLS·RPC는 격리된 테스트 환경이나 합의된 테스트 데이터로 확인한다. 공용 DB의 기존 데이터를 임의 변경하지 않는다.
