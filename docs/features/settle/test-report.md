## 2. REQ-SETTLE-04 주문중 자동 전환 (#51)

- 검증일: 2026-10-30
- 환경: 실제 Supabase, 사용자 로컬 앱과 계정 2개(Host H, 참여자 P)
- 결과 대조: `supabase db query --linked` 읽기 전용 조회

### 예약 작업 상태

| 항목 | 결과 |
|---|---|
| `close-due-meals` 등록 | 1분마다, 활성 |
| 최근 1일 실행 | 1,440회, 모두 성공 |
| 예정 시간이 2분 이상 지난 모집중 겸상 | 0건 |

### 테스트 겸상

| 겸상 | 준비 | 전환 후 상태 | 남은 참여자 |
|---|---|---|---|
| X | H 메뉴 없음, P 메뉴 1개·미확정 | 주문중 | H(메뉴 0, 미확정), P(메뉴 1, 미확정) |
| Y | H 메뉴 1개, P 메뉴 없음 | 주문중 | H만 (P 제외) |
| Z | H 혼자, 메뉴 없음 | 취소 | H |

- 각 상세 화면에서 상태 변경이 새로 고침 없이 반영됨 (#81 `meals` 구독)

### 검증 한계

- 주문 예정 시간이 분 단위이고 예약 작업도 매분 실행되어, 예정 시간 경과 후 상태 전환 전 구간의 변경 차단은 실환경에서 재현하지 않음. 같은 `is_meal_open` 기준의 차단은 join 격리 DB 검증 결과를 따른다.
