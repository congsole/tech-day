# 주문 + 정산 화면 설계

담당: congsole (통합·스키마). 요구사항은 `docs/features/settle/requirements.md`, 공통 표현은 `docs/common/design-system.md`를 따른다.

## 1. 위치와 표시 대상

- 경로: `/meals/:id` 겸상 상세의 settle 섹션 (로그인 필요). 상세의 맨 아래, join 섹션(Host 취합 현황 SCR-JOIN-03 포함) 다음에 둔다
- 겸상 상태와 보는 사람에 따라 아래만 표시한다. 표에 없는 경우에는 settle 섹션에 아무것도 표시하지 않는다

| 겸상 상태 | Host | Host가 아닌 참여자 | 참여자가 아닌 사용자 |
|---|---|---|---|
| 모집중 | 없음 | 없음 | 없음 |
| 주문중 | SCR-SETTLE-ORDER | 없음 | 없음 |
| 주문완료 | SCR-SETTLE-LIST, SCR-SETTLE-START | SCR-SETTLE-LIST | 없음 |
| 정산 | SCR-SETTLE-LIST | SCR-SETTLE-LIST | 없음 |
| 취소 | 없음 | 없음 | 없음 |

- 상태 배지는 겸상 정보(SCR-MEAL-INFO)가 표시하므로 settle 섹션에서 상태 이름을 따로 표시하지 않는다

### SCR-SETTLE-ORDER 주문완료 전환
- 관련 요구사항: REQ-SETTLE-01
- 표시 대상: 주문중 겸상의 현재 Host
- 구성: 카드 하나
  - 안내 문구 "취합 현황대로 주문을 넣은 뒤 주문완료로 바꿔 주세요."
  - "주문완료" 버튼(핵심 행동. 채움형)
- 동작: "주문완료"를 누르면 확인 대화상자(SCR-SETTLE-ORDER-CONFIRM)를 연다

### SCR-SETTLE-ORDER-CONFIRM 주문완료 확인 대화상자
- 위치: 겸상 상세 위에 겹쳐 열리는 대화상자. 별도 경로는 없다
- 관련 요구사항: REQ-SETTLE-01
- 구성
  - 제목 "주문완료"
  - 안내 문구 "주문완료로 바꾸면 되돌릴 수 없습니다. 주문을 넣었는지 확인해 주세요."
  - "돌아가기"(보조), "주문완료"(핵심 행동. 채움형) 버튼을 오른쪽 정렬
- 동작
  - "주문완료"를 선택해야 전환을 요청한다(`mark_meal_ordered`)
  - 처리 중: "주문완료" 버튼에 로딩 표시, 중복 요청 방지
  - 성공: 대화상자를 닫고 상세에 머문다. 상태 배지가 "주문완료"로 바뀌고 정산 내역(SCR-SETTLE-LIST)과 정산 시작(SCR-SETTLE-START)이 보인다
  - 실패: 대화상자에 안내를 표시하고 전환 성공으로 처리하지 않는다
    - 주문중이 아님(`invalid_status`): "주문중일 때만 주문완료로 바꿀 수 있습니다."
    - Host가 아님(`not_host`): "Host만 주문완료로 바꿀 수 있습니다."
    - 그 밖의 오류: "주문완료로 바꾸지 못했습니다. 다시 시도해 주세요."
  - 돌아가기, 바깥 누르기, Esc: 전환하지 않고 닫는다

### SCR-SETTLE-LIST 정산 내역
- 관련 요구사항: REQ-SETTLE-02
- 표시 대상: 주문완료·정산 겸상의 Host와 참여자
- 구성: 카드 하나
  - 영역 제목 "정산 내역"
  - 참여자 목록: 참여 순서대로 참여자마다 표시 이름과 부담액(`12,000원` 형식)을 한 줄에 둔다. 이름이 길면 줄바꿈하고 금액은 오른쪽 정렬을 유지한다
  - 메뉴가 없는 참여자(메뉴 없이 남은 Host)는 부담액 `0원`
  - 마지막에 구분선과 "총액"을 두고 총액을 굵은 글자로 강조한다 (`docs/common/design-system.md` 금액)
  - 이메일과 메뉴명은 표시하지 않는다. Host의 참여자별 메뉴·이메일은 SCR-JOIN-03에서 본다
- 데이터: `docs/common/db-schema.md` §9 참여자별 부담액. 부담액은 본인 메뉴 항목 금액의 합(1/N 아님), 총액은 그 겸상의 메뉴 항목 금액의 합
- 상태 표현
  - 불러오는 중: 최초 조회에만 로딩 표시. 다시 조회하는 동안에는 이전 내역을 유지한다
  - 조회 실패: 카드 안에 "정산 내역을 불러오지 못했습니다. 새로 고침해 주세요." 실패를 빈 목록이나 0원으로 대체하지 않는다

### SCR-SETTLE-START 정산 시작
- 관련 요구사항: REQ-SETTLE-03
- 표시 대상: 주문완료 겸상의 현재 Host
- 구성: 정산 내역(SCR-SETTLE-LIST) 카드 아래에 "정산 시작" 버튼(핵심 행동. 채움형)
- 동작: "정산 시작"을 누르면 확인 대화상자(SCR-SETTLE-START-CONFIRM)를 연다

### SCR-SETTLE-START-CONFIRM 정산 시작 확인 대화상자
- 위치: 겸상 상세 위에 겹쳐 열리는 대화상자. 별도 경로는 없다
- 관련 요구사항: REQ-SETTLE-03
- 구성
  - 제목 "정산 시작"
  - 안내 문구 "정산을 시작하면 되돌릴 수 없습니다."
  - "돌아가기"(보조), "정산 시작"(핵심 행동. 채움형) 버튼을 오른쪽 정렬
- 동작
  - "정산 시작"을 선택해야 전환을 요청한다(`start_settlement`)
  - 처리 중: "정산 시작" 버튼에 로딩 표시, 중복 요청 방지
  - 성공: 대화상자를 닫고 상세에 머문다. 상태 배지가 "정산"으로 바뀌고 "정산 시작" 버튼이 사라진다
  - 실패: 대화상자에 안내를 표시하고 전환 성공으로 처리하지 않는다
    - 주문완료가 아님(`invalid_status`): "주문완료일 때만 정산을 시작할 수 있습니다."
    - Host가 아님(`not_host`): "Host만 정산을 시작할 수 있습니다."
    - 그 밖의 오류: "정산을 시작하지 못했습니다. 다시 시도해 주세요."
  - 돌아가기, 바깥 누르기, Esc: 전환하지 않고 닫는다

## 2. 갱신

- 상태 전환 성공 후 겸상 상세의 공유 데이터를 다시 조회한다(#75). 다른 사용자의 화면은 `meals` 실시간 구독(#81, `docs/common/db-schema.md` §10)으로 새로 고침 없이 바뀐다
- 정산 내역은 공유 데이터가 다시 조회될 때마다 다시 조회한다. 주문중 이후에는 참여와 메뉴가 잠기므로 settle에서 별도 구독을 추가하지 않는다
- 조회가 겹치면 마지막 요청의 응답만 반영한다

## 3. 화면 검토 체크리스트

| 근거 | 확인할 장면 |
|---|---|
| REQ-SETTLE-01 | Host의 주문완료 전환, Host가 아닌 참여자에게 버튼 미표시, 주문중이 아닐 때 안내 |
| REQ-SETTLE-02 | 참여자별 부담액·강조된 총액, 메뉴 없는 Host 0원, 모집중·주문중·취소와 비참여자에게 미표시 |
| REQ-SETTLE-03 | Host의 정산 시작, Host가 아닌 참여자에게 버튼 미표시, 주문완료가 아닐 때 안내 |
| 공통 | 확인 대화상자의 돌아가기·Esc, 처리 중 중복 요청 방지, 다른 탭의 새로 고침 없는 상태 반영, 모바일 줄바꿈 |
