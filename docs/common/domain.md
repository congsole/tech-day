# 도메인 설계, 용어집

겸상의 도메인 모델과 용어를 정의한다. 기능 규칙(정산 방식, 정원 처리 등)은 `docs/common/planning.md` §3에 있으며, 여기서는 **용어의 뜻과 관계·상태**를 정의한다.

## 용어집

| 용어 | 코드/영문 | 정의 |
|---|---|---|
| 겸상 | Meal | 같이 식사하거나 배달을 함께 시킬 사람을 모으는 모임 하나. Host가 연다 |
| 여는 사람 | Host | 겸상을 생성한 사람. 정원·주문 예정 시간 등을 정하고 주문완료·정산을 진행 |
| 참여자 | Member | 겸상에 참여한 사람. 자기 메뉴를 입력하고 주문 확정 |
| 사용자 | User | 이메일 OTP로 인증한 사람. 하나의 이메일이 하나의 신원. 표시 이름을 가짐 |
| 표시 이름 | displayName | 화면에 보이는 이름으로 **본명(실명)을 입력**한다. 첫 로그인 때 설정. 동명이인이 있을 수 있으며 신원 구분은 이메일로 한다 |
| 유형 | type | 겸상의 종류. `식사`(같이 식사) 또는 `배달`(배달 소분). 표시용 구분만 |
| 메뉴 항목 | OrderItem | 참여자가 입력한 주문 한 줄. 메뉴명 + 금액(원, 정수)으로 구성 |
| 주문 확정 | confirm | 참여자가 자기 메뉴를 미리 잠그는 선택적 행동. 확정하면 본인 메뉴가 잠기고 확정 시각이 기록됨. 안 해도 주문중 진입 시 자동 잠김 |
| 부담액 | amountDue | 참여자가 낼 금액. 본인이 입력한 메뉴 항목 금액의 합 |
| 정원 | capacity | Host가 정한 최대 참여 인원 |
| 주문 예정 시간 | orderTime | Host가 주문을 넣을 예정 시각. 이 시각이 되면 겸상이 자동으로 `주문중`으로 잠긴다(참여·메뉴 변경·취소 불가). Host 넘기기 수락 마감 기준. 모집중에 Host가 현재 이후 시각으로 수정 가능(Host 넘기기 대기 중 제외) |
| 집합/수령 장소 | place | 같이 식사의 집합 장소 또는 배달 수령 장소. Host가 정하고 수정 |
| 공지 | Notice | Host만 올리는 알림. 배달 위치·배달 완료·변경 사항 등. 참여자는 읽기 전용 |
| 상태 | status | 겸상의 진행 단계. `모집중` / `주문중` / `주문완료` / `정산` / `취소` |

## 관계

```
User(Host) ─1──* 겸상(Meal) ─1──* 참여(Member) ─1──* 메뉴 항목(OrderItem)
                                      └ Member 1명당 User 1명 (이메일 신원)
```

- 한 겸상에는 Host 1명과 Member 여러 명이 있다. Host는 생성 시 자동으로 Member가 되며 정원에 포함된다. Host는 참여 취소가 불가하다(빠지려면 Host 넘기기 또는 겸상 취소).
- 한 Member는 메뉴 항목을 **0개 이상** 가진다. 부담액 = 그 금액의 합.
- 한 User(이메일)는 한 겸상에 한 번만 참여한다.
- 한 겸상에는 공지(Notice)가 여러 개 있을 수 있고, **Host만** 작성한다.

## 상태 모델

```
모집중 ──(주문 예정 시간: 자동)──▶ 주문중 ──(Host: 주문완료)──▶ 주문완료 ──(Host: 정산 시작)──▶ 정산
  └──(Host: 즉시 취소 / Host 넘기기 실패 / 주문중 전환 때 메뉴 0개)──▶ 취소
```

| 상태 | 뜻 | 이 상태에서 가능한 것 |
|---|---|---|
| 모집중 | 참여를 받는 중 | 참여/취소(Host 제외), 메뉴 입력·수정(본인 확정 전까지), 주문 확정, 주문 예정 시간 수정, Host 넘기기, Host의 겸상 취소 |
| 주문중 | 주문 예정 시간에 자동 잠김. Host가 실제 주문을 넣는 중 | 변경 전부 불가. 진입 시 메뉴 미입력자 제외(Host 제외 안 함) |
| 주문완료 | Host가 주문을 넣음 | 수정 불가. 부담액 확인 |
| 정산 | 금액을 나눠 보는 중 | 참여자별 부담액·총액 표시 |
| 취소 | 무산됨 (Host 즉시 취소 / 넘기기 실패 / 주문중 때 메뉴 0개) | 목록에서 제외. 더 이상 참여 불가 |

- 겸상 취소 경로: ① 모집중에 Host가 사유를 적고 즉시 취소 ② Host 넘기기가 주문 예정 시간까지 미수락이거나 전원 거절 ③ 주문중 전환 시 메뉴 입력자가 0명.
- Host 넘기기: Host가 사유를 적고 Host 역할을 넘긴다. 참여자 1명이 수락하면 새 Host가 되고 겸상은 유지되며, **수락 시 기존 Host의 참여·메뉴는 삭제**된다. 다른 참여자가 없으면 넘기기 요청 불가(겸상 취소 사용). 대기 중 Host가 겸상을 취소하거나 다른 참여자가 모두 나가면 요청은 닫히고 겸상은 취소된다.

- `모집중 → 주문중`은 주문 예정 시간에 자동으로, 그 이후 전환은 **Host가 수동**으로 한다.
- 참여자의 "주문 확정"은 겸상 상태와 별개인 **본인 메뉴의 잠금**이다. 선택 사항이며, 주문중 전환 전에 미리 잠그는 용도다.

## 도메인 판단 (요약)

아래 판단의 상세 규칙은 `docs/common/planning.md` §3을 따른다.

- 신원은 이메일, 책임은 "이메일 + 주문 확정 기록"으로 성립한다 → "안 시켰다" 발뺌 방지.
- 표시 이름은 본명으로 쓴다. 본명 여부는 기술로 강제하지 못하므로 신뢰 기반이며, Host는 참여자의 이메일로 신원을 확인할 수 있다.
- Host는 참여자의 이메일 주소를 볼 수 있다 (취합·정산 연락용). 참여자끼리는 이메일을 보지 않는다.
- 정산은 1/N이 아니라 **각자 주문 금액대로**다.
- 정원이 차면 마감되지만, 취소로 자리가 나면 자동으로 다시 참여받는다.
