# 공통 디자인

> 공통 디자인 확정안. 기존 초안의 색·간격·레이아웃·컴포넌트 기준을 구현 규칙으로 정리했다. 이 변경은 작성자 제외 전원의 승인과 dev 머지 후 팀의 확정 기준으로 적용한다.

- 담당: yooge0902 (검증·디자인)
- 근거: `docs/common/planning.md` §5 디자인 담당, `docs/common/domain.md` 상태 모델
- 적용 범위: meal·join·settle·notice 전체 화면

## 1. 목적과 범위

세 명의 개발자가 각자의 AI 에이전트로 화면을 구현해도 일관된 UI를 만들기 위한 최소 기준이다.

- 기존 기획: 사내 직원용 반응형 웹앱, 모바일 우선. `docs/common/planning.md` §1·§2 참조
- 용어와 상태: `docs/common/domain.md` 용어집·상태 모델 참조
- 이 문서는 공통 표현을 다룬다. 화면별 구성과 기능 동작은 각 기능의 요구사항·화면 설계를 따른다.

## 2. UI 라이브러리와 비용

UI 라이브러리는 Mantine **9.7.3**을 사용한다. 초기에는 `@mantine/core`와 `@mantine/hooks`를 동일한 `9.7.3`으로 고정하고, `package-lock.json`을 공유한다. AI 에이전트는 설치 버전에 맞는 API를 참고한다. Mantine 설치·빌드·린트 호환성을 검증했다(2026-10-26). Theme 검증 범위와 남은 화면 검증은 `docs/common/theme-test-report.md`에 기록한다. 호환성 문제로 버전 변경이 필요하면 이 문서부터 수정한다. [공식 릴리스](https://github.com/mantinedev/mantine/releases/tag/9.7.3)

공식 Mantine 패키지는 MIT 라이선스로 무료 사용 가능하다. [공식 라이선스 안내](https://mantine.dev/getting-started/) (확인일: 2026-10-18)

- UI 개발·실행에 개인 결제가 필요한 도구·자산이나 유료 전환이 필요한 체험판에 의존하지 않는다.
- MIT 라이선스의 저작권·라이선스 고지는 보존한다.

## 3. 기본 시각 규칙

식사 모임에 어울리는 친근하고 단정한 화면을 지향한다. 메뉴·금액·진행 상태를 명확하게 표시한다.

아래 값은 프로젝트의 디자인 기준이며, Mantine 기본값을 그대로 설명한 표가 아니다.

| 항목 | 기준 |
|---|---|
| 테마 | 이번 범위는 라이트 모드만 사용 |
| 글꼴 | 운영체제 기본 글꼴. 별도 폰트 구매·다운로드 없이 구성 |
| 글자 크기 | 화면 제목 24px, 영역 제목 20px, 본문 16px, 보조 설명 14px |
| 간격 | 4·8·12·16·24·32px 단계 사용 |
| 모서리 | 입력창·버튼 8px, 카드 12px |
| 그림자 | 기본적으로 테두리로 구분하고 그림자는 최소 사용 |

색·간격·글자 크기는 공통 Theme 값으로 관리한다.

### 색상

별도 팔레트를 만들지 않고 Mantine 기본 색상을 다음 역할로 사용한다. [공식 색상 값](https://mantine.dev/styles/css-variables-list/)

| 용도 | Mantine 색상 | HEX |
|---|---|---|
| 주요 버튼·링크·포커스 | `teal.9` | `#087F5B` |
| 연한 강조 배경 | `teal.0` | `#E6FCF5` |
| 전체 화면 배경 | `gray.0` | `#F8F9FA` |
| 카드·입력창 배경 | `white` | `#FFFFFF` |
| 제목·본문 | `gray.9` | `#212529` |
| 보조 설명 | `gray.7` | `#495057` |
| 카드·영역 구분선 | `gray.3` | `#DEE2E6` |
| 입력창 테두리 | `gray.6` | `#868E96` |
| 비활성 배경 | `gray.1` | `#F1F3F5` |
| 비활성 글자 | `gray.6` | `#868E96` |

주요 버튼은 `teal.9` 배경과 흰색 글자, 연한 강조는 `teal.0` 배경과 `teal.9` 글자를 조합한다.

| 의미 | 글자·아이콘 | 배경 |
|---|---|---|
| 오류·위험 | `red.9` — `#C92A2A` | `red.0` — `#FFF5F5` |
| 주의 | `orange.9` — `#D9480F` | `orange.0` — `#FFF4E6` |
| 성공 | `green.9` — `#2B8A3E` | `green.0` — `#EBFBEE` |

색만으로 상태를 전달하지 않고 문구를 함께 표시한다. 실제 컴포넌트의 hover·focus·disabled 조합과 가독성은 Theme 구현 시 확인한다.

## 4. 레이아웃·컴포넌트

### 반응형 기준

Mantine 기본 `sm` 값인 **48em**을 기준으로 두 구간만 사용한다. 기본 글꼴 환경에서는 768px에 해당한다. 다른 기본 breakpoint는 유지하되 초기 화면에서는 `base`와 `sm`만 사용한다. [공식 반응형 기준](https://mantine.dev/styles/responsive/)

| 항목 | 48em 미만 | 48em 이상 |
|---|---|---|
| 화면 좌우 여백 | 16px | 24px |
| 기본 배치 | 단일 열 | 단일 열 유지, 화면 설계에 따라 필요한 경우만 가로 배치 |
| 본문 너비 | 사용 가능한 너비 | 최대 960px, 가운데 정렬 |
| 입력 폼 너비 | 사용 가능한 너비 | 최대 560px, 가운데 정렬 |

화면이 넓어진다는 이유만으로 자동으로 2열로 전환하지 않는다. 가로 배치가 필요한 경우 해당 기능의 화면 설계에서 정한다.

### 컴포넌트

| 항목 | 규칙 |
|---|---|
| 버튼 | 핵심 행동은 채움형, 보조 행동은 외곽선·연한 배경. 삭제·취소 등 위험 행동은 문구와 색으로 구분 |
| 입력창 | Mantine 기본 입력 컴포넌트 사용. 라벨은 항상 표시하고 오류는 해당 입력창 아래에 표시 |
| 목록·카드 | 겸상 단위로 구분. 제목·유형·인원 등 표시 내용은 해당 기능 요구사항을 따름 |
| 상태 배지 | 겸상은 모집중·주문중·주문완료·정산·취소, 개인 주문은 미확정·확정됨으로 구분하여 표시 |
| 금액 | `12,000원` 형식. 합계는 글자 굵기로 강조 |
| 공통 구현 | Mantine 컴포넌트를 우선 직접 사용. 실제로 반복되는 구성만 공통 컴포넌트로 추출 |

기능마다 기본 버튼·입력창을 새로 만들거나 다른 UI 라이브러리를 혼용하지 않는다. 화면별 스타일 예외는 최소화한다.

겸상의 상태와 개인 주문 확정 상태는 별도로 표시한다. 예를 들어 모집중인 겸상에서도 내 메뉴는 확정됨 상태일 수 있다. 주문중으로 자동 잠겨도 개인 주문은 미확정일 수 있다. 자동 잠금을 확정됨으로 표시하지 않는다. 상태의 의미는 `docs/common/domain.md` 상태 모델·주문 확정 용어를 따른다.

## 5. 상태 표현·사용성

| 상황 | 규칙 |
|---|---|
| 로딩 | 처리 중임을 표시 |
| 빈 화면 | 모집중인 겸상이 없습니다 등 현재 상황을 설명 |
| 입력 오류 | 이해 가능한 안내를 해당 입력창 아래에 표시 |
| 요청 실패 | 관련 영역에 실패 안내 표시 |
| 잠금 | 비활성 색과 함께 잠금 이유 표시. 예: 주문 확정 후에는 수정할 수 없습니다 |
| 터치 조작 | 주요 터치 영역은 최소 44×44px을 목표로 구성 |
| 키보드 조작 | 키보드 포커스 표시 유지 |

## 6. 적용과 검토

- 이 문서는 공통 표현 기준을 정한다. Host 참여 취소 등 업무 규칙은 각 기능 요구사항과 공통 기획에서 결정한다.
- 화면별 배치와 확인 대화상자 유무는 해당 기능의 화면 설계에서 정한다. 이 문서만으로 새로운 사용자 동작을 추가하지 않는다.
- 최초 UI 구현에서 공통 Theme에 색·간격·글자 크기를 반영하고, 실제 버튼·입력창의 hover·focus·disabled 상태와 가독성을 확인한다.
- 모바일·데스크톱에서 줄바꿈, 키보드 조작, 오류·잠금 문구, 금액 표시를 검증한다. 결과는 해당 기능의 테스트 결과서에 기록한다.
