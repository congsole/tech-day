# 기획서

## 1. 개요

겸상은 사내 직원이 **같이 점심·저녁을 먹거나 배달을 함께 시킬 사람을 모으는 웹앱**이다.
누군가 겸상을 열면 다른 직원이 참여하고, 참여자가 각자 메뉴를 올리면 Host가 취합해 주문한 뒤 각자 낼 금액을 정산한다.

- 사용자: 사내 직원
- 형태: **웹앱 (반응형, 모바일 우선 디자인)**. 지금은 웹으로 만들고, 추후 **PWA/네이티브로 모바일 확장**이 가능하도록 둔다
- 스택: React + Supabase
- 용어: 겸상 = Meal, 여는 사람 = Host, 참여자 = Member (상세는 `docs/common/domain.md`)

## 2. 범위

핵심 흐름 하나를 끝까지 도는 것까지만 만든다.

```
겸상 열기 → 참여 → 메뉴 취합 → 주문 → 정산
```

상태 흐름: `모집중 → 주문중 → 주문완료 → 정산`
`모집중 → 주문중`은 **주문 예정 시간에 자동**으로, 그 이후는 **Host가 수동**으로 전환한다.
참여자는 모집중 단계에서 메뉴를 넣고 **"주문 확정"**(선택)을 누르면 본인 메뉴가 잠긴다. 주문 예정 시간이 되면 겸상 전체가 `주문중`으로 잠겨 더 이상 바꿀 수 없다.

### 비범위 (이번엔 만들지 않음)

- 실제 결제·송금 연동 (금액은 **표시만**, 돈은 앱 밖에서 주고받음)
- 금액 조정: 실제 주문 금액과 입력 금액의 차이, 배달비·최소주문금액 같은 공통 비용은 앱에서 다루지 않는다 (필요하면 Host가 공지로 안내)
- 비밀번호 로그인 (대신 이메일 OTP 간편 인증 사용)
- 참여자 간 채팅(공지는 Host만 가능), 푸시 알림(앱 외부), 내 겸상에서 빠진 지난 겸상(주문 예정 시간 7일 경과한 정산·취소 겸상)의 내역 조회
- 네이티브 모바일 앱 (이번엔 반응형 웹만. 모바일 확장은 추후 PWA/네이티브로)

## 3. 기획 판단 (확정된 규칙)

도메인 판단이 갈리지 않도록 아래를 기획에서 확정한다. (`docs/common/domain.md`와 함께 관리)

| 항목 | 결정 |
|---|---|
| 사용자 식별 | **이메일 OTP 간편 인증** (사내 이메일 1회, 비밀번호 없음). 표시 이름은 첫 로그인 때 **본명(실명)으로** 설정. 이메일이 고유 신원 |
| 개인정보 노출 | **Host는 참여자의 이메일 주소를 볼 수 있다** (취합·정산 연락용). 참여자 간에는 이메일을 노출하지 않는다 |
| 주문 확정 | 참여자가 메뉴 입력 후 **"주문 확정"**(선택) 1탭 → 본인 메뉴를 미리 잠그고 시각 기록. 안 눌러도 주문 예정 시간에 자동 잠김. 확정 기록으로 "안 시켰다" 발뺌 방지 |
| 겸상 유형 | **같이 식사 / 배달 소분** 둘 다. 기능 차이 없이 **표시 태그**로만 구분 |
| 겸상 열기 입력 | 제목, 유형, **식당/가게명**, **집합/수령 장소**, **주문 예정 시간**, 정원(최대 인원)은 필수. **가게 메뉴판 링크**, 메모는 선택 |
| 메뉴판 공유 | Host가 가게 링크를 올리면 참여자가 **링크로 외부 메뉴판을 직접 본다**. 앱이 메뉴를 끌어오거나 저장하지 않음 |
| 집합/수령 장소 | 같이 식사는 집합 장소, 배달은 수령 장소. 겸상 열 때 **반드시 입력**하고 Host가 수정할 수 있다(비울 수 없음). 참여자 모두에게 표시 |
| Host 공지 | **Host만** 공지를 올린다(참여자는 읽기 전용). 배달 위치·배달 완료·변경 사항 등 상황 공유 |
| 주문 예정 시간 | Host가 주문을 넣을 예정 시각. **이 시각이 되면 겸상이 자동으로 `주문중`으로 잠긴다**(참여·메뉴 변경·취소 모두 불가). **Host 넘기기 수락 마감** 기준이기도 하다. **모집중일 때 Host가 현재 이후 시각으로 수정**할 수 있으나, **Host 넘기기 대기 중에는 수정 불가** |
| 주문중 전환 | 주문 예정 시간이 되면 자동으로 `주문중`이 되어 **참여·취소·메뉴 변경이 모두 잠긴다**. 이때 **메뉴를 하나도 입력하지 않은 참여자는 제외**된다(단, Host는 제외하지 않는다). 메뉴를 입력했으면 확정 여부와 무관하게 포함. **제외 후 메뉴 항목이 하나도 남지 않으면 주문중 대신 `취소`로 전환**된다 |
| 정원 | Host가 설정. **정원이 차면 참여 불가(마감)**. 동시 참여 시 초과되지 않게 처리. 취소로 자리가 나면 **자동으로 다시 참여 가능** |
| Host 참여 | Host는 겸상 생성 시 **자동으로 참여자가 되며 정원에 포함**된다. Host도 메뉴를 입력하고 주문 확정한다. **Host는 참여 취소가 불가**하며(빠지려면 Host 넘기기 또는 겸상 취소), **메뉴가 없어도 주문중 전환 때 제외되지 않고 부담액 0원으로 유지**된다 |
| 메뉴 취합 | 참여자가 **자유 텍스트로 메뉴명 + 금액** 직접 입력 |
| 정산 방식 | **각자 주문 금액대로** (1/N 아님). 각자 입력한 금액 합이 본인 부담액 |
| 수정·취소 | **모집중이며** 본인이 "주문 확정"을 누르기 전까지 메뉴·금액 수정과 참여 취소 가능(단 Host는 취소 불가). 확정 후 또는 주문중 진입 후에는 잠김 |
| 재참여 | 주문중 전(모집중)이면 취소 후 다시 참여할 수 있다. **재참여 시 기존 메뉴는 초기화**(삭제)된다 |
| 목록 화면 | **모집중 목록**: 모집중이고 주문 예정 시간 전인 겸상만 노출 (취소된 겸상 제외). **내 겸상**: 내가 Host이거나 참여 중인 겸상을 **상태와 관계없이** 노출하고 상세로 들어갈 수 있다. 끝난 겸상(정산·취소)은 **주문 예정 시간 기준 최근 7일**까지만 노출 |
| 겸상 취소 | **모집중일 때 Host가 사유를 적고 겸상을 바로 취소**할 수 있다. 취소된 겸상은 모집중 목록에서 제외된다 (내 겸상에는 노출) |
| Host 넘기기 | Host가 Host 역할만 넘기고 겸상은 유지하려 할 때 쓴다. Host가 사유를 적고 넘기면 참여자 한 명이 수락해 **새 Host가 되고 겸상은 유지**된다. **수락 시 기존 Host의 참여와 메뉴 항목은 삭제**된다(이탈). 아무도 수락하지 않거나(**주문 예정 시간까지** 미수락) **전원 거절하면 겸상이 취소**된다 |
| 통화 단위 | 원(KRW), 정수 |

각자 API부터 화면까지 한 줄기를 맡는다. 슬라이스는 서로 기다리지 않도록 잘랐다.

| 슬라이스 | 기능 | 담당 | 비고 |
|---|---|---|---|
| **A. 인증 + 겸상 열기 + 목록** | 이메일 OTP 로그인·표시 이름 설정, 겸상 열기(제목·유형·식당/가게명·집합/수령 장소·주문 예정 시간·정원·메뉴판 링크·메모), 모집중 목록·내 겸상 보기 | **wgmin0416 (컨텍스트·기획)** | 진입 흐름 |
| **B. 참여 + 메뉴 + 주문 확정** | 겸상 참여(정원 체크), 메뉴명+금액 입력, 수정·취소, **주문 확정(잠금)**, Host의 취합·확정 현황 보기 | **yooge0902 (검증·디자인)** | 화면·폼 중심 |
| **C. 주문 + 정산** | Host 주문완료 전환(확정 현황 확인), 정산 화면(참여자별 부담액·총액 표시) | **congsole (통합·스키마)** | 데이터·로직 중심 |
| **공지** | Host 공지 작성, 참여자 열람 (집합/수령 장소·배달 위치·배달 완료 공유) | **congsole (통합·스키마)** | Host 소통. 주문·정산과 함께 담당 |
