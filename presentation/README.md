# 겸상 — Reveal.js 발표 자료

`docs/presentation-plan.md`의 2026-11-05 세 막 구성 개정안(문서 커밋 `a93a2f4`)을 기준으로 본편 22장에 상황극 3편을 더해 총 25장으로 구성했습니다. 주제 선정부터 세 사람의 회고까지 구성안의 순서·핵심 메시지·사례를 유지합니다. 본편 21분 50초, 상황극 1분 50초, 현장 여유 40초를 합쳐 약 24분 20초이며, 질의응답은 별도입니다.

## 실행 및 복사

`presentation` 폴더 전체를 다른 PC로 복사한 뒤 `index.html`을 Chrome 또는 Edge에서 여세요. HTML·CSS·JavaScript와 Reveal.js를 모두 로컬 파일로 포함했습니다. 빌드·npm 설치·인터넷 없이 실행하도록 구성했으며, 실행 중 Markdown 원본을 읽지 않으므로 이 폴더만 옮기면 됩니다.

브라우저에서 로컬 서버로 확인하고 싶다면 저장소 루트에서 다음 명령을 실행하고 `http://localhost:8765`를 여세요. 서버는 선택 사항입니다.

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory presentation
```

- 오른쪽 화살표 / Space: 다음 요소 등장 → 다음 슬라이드
- 왼쪽 화살표: 이전 요소 / 슬라이드. 16·21장의 화면 변화도 이전 단계로 복원
- 화면 하단 ← / → 버튼: 마우스·터치로 동일한 순차 이동
- F: 전체 화면, Esc: 전체 보기
- S 또는 발표자 노트 버튼: 별도 노트 창. 팝업 차단 시 팝업 허용 후 다시 실행
- 노트 창: 이전·다음 버튼, 좌우 화살표·Space로 제어. 현재 클릭 단계의 대본을 강조하고 해당 위치로 이동. 연출 의도·현재 화면·무대 지시·다음 클릭 시점·출처·예상 시간 표시

프로젝터에는 발표 화면만 표시하고, 노트 창은 발표자 화면에 두세요. 표기 시간은 계획 시간이며 자동 넘김이나 실시간 타이머가 아닙니다. 화면에서 회고의 화자·출처 표시는 빼고, 출처와 개인 의견의 범위는 노트에 남겼습니다. 작성·연출 주의사항과 회고 원문은 접힌 참고 항목으로 분리했습니다.

모바일에서는 가로 화면을 사용하세요. 파일 관리 앱의 HTML 미리보기는 JavaScript를 실행하지 않을 수 있으므로 브라우저로 열어야 합니다. PC의 파일 경로를 휴대폰에서 바로 열 수는 없습니다. 모바일 공유·접속에는 정적 호스팅 주소를 사용할 수 있습니다.

## 대본과 애니메이션 함께 보기

`S`를 누르면 본편 22장·70단계의 긴 발표 대본을 볼 수 있습니다. ‘시작’은 클릭 전 화면, ‘클릭 1 이후’는 첫 요소가 나타난 상태입니다. 현재 단계의 대본을 읽고, 아래 ‘다음 조작’ 안내에 맞춰 진행하세요. 뒤로 이동하면 강조되는 대본도 이전 단계로 돌아갑니다.

회색의 연출 의도·현재 화면·무대 지시는 낭독하지 않습니다. 큰 글씨 문단이 실제 읽을 대본입니다. 같은 단계에서 창을 스크롤하거나 출처를 펼쳐도 상태를 유지하고, 단계가 바뀔 때만 해당 대본으로 이동합니다. 원래 구성 메모와 근거는 하단의 접힌 참고에 보존했습니다.

폴더의 `speaker-script.md`에는 같은 대본과 클릭 안내가 들어 있어 브라우저 없이 읽거나 인쇄할 수 있습니다. 실행 중 이 Markdown 파일을 읽어들이지는 않습니다. 대본 문장을 편집한다면 `index.html`의 노트와 함께 맞춰야 합니다.

기존 계획 시간은 유지했습니다. 이번 긴 대본을 그대로 읽는 데 걸리는 시간은 아직 실측하지 않았으므로 리허설에서 호흡·클릭 시간을 포함해 확인하세요.

## 구현상 조정

구성안의 내용·순서·시간을 유지하며, 발표 전달을 위한 노트를 보완했습니다. 9장에서 도입 사건을 짧게 상기하고, 13–17장에는 사례별로 짚을 한 문장을 노트에 넣었습니다. 19장 뒤는 담백하게 전환하며, 21장은 각 방향을 앞의 경험과 연결해 설명합니다. 이 문장들은 기존 설명을 마무리할 때 활용하는 표현으로, 별도 사례나 순차 등장 단계를 추가하지 않습니다.

각 장 상단에 현재 막을 표시합니다. 별도의 막 구분 슬라이드는 추가하지 않았습니다. 기존 종이색 배경과 강조색, 타이포그래피를 유지하고 새 이야기의 화면 구성을 추가했습니다. 화면 문구는 가독성을 위해 줄바꿈하거나 짧게 표현했으며, 상세 설명과 근거는 발표자 노트에 담았습니다.

- 2장: 초기 아이디어는 같은 크기로 표시하고 겸상을 최종 선택으로 노출합니다. 사람별 아이디어의 규모를 비교하지 않습니다.
- 4·5·13장: 역할 조정, 합의 가능한 기획, 개인 맥락에만 남은 결정을 팀에서 있었던 일 중심으로 표시합니다. 이름은 역할 분담처럼 설명에 필요한 곳만 유지합니다.
- 10장: 논의·본업 복귀·PR 제출·승인 대기를 팀 전체의 경험을 요약한 도식으로 표현했습니다. 실접속 기록처럼 보이지 않도록 표시하고, 클릭마다 한 번만 짧은 등장 효과를 사용합니다.
- 11·18장: PR #104의 리뷰·수정 이력과 직접 사용하며 발견한 문제를 각각 표시합니다.
- 16장: 결함 재현 표가 등장할 때 앞의 관점 목록을 접어 공간을 확보합니다. 모의·실환경 검증 구분은 유지합니다.
- 15·17장: 기존의 머지 순서와 리뷰 지적 처리 사례를 별도 장으로 나눴습니다. 16장에서 도입 사건을 회수한 직후, 17장에서 #102 지적 → #115 첫 배포 → #117 수정 흐름을 단계별로 보여줍니다. 기존 100초를 60초·40초로 나눠 전체 시간과 내용은 유지합니다.
- 20장: 사람·화면·배포 사이에서 앞 작업의 결과가 이어지지 않았던 세 장면을 되짚습니다.
- 21장: 기획·규약, 운영 절차, 확인·판단 분담이라는 다음 방향을 순차 표시한 뒤 각 선택의 이유를 짚습니다. 22장은 첫 장의 검토 세 번과 세 사람의 협업을 연결해 마무리합니다. 사건 경위는 17장에서 설명하고 여기서는 각자의 해석과 다음 선택에 집중합니다.

모든 전환은 발표자가 제어합니다. 자동 재생·반복 애니메이션·영상·영상 자리 표시자는 없습니다. OS의 모션 감소 설정에서는 CSS 전환과 애니메이션을 끕니다.

## 파일 구성과 오프라인 동작

- `index.html`: 22장 본문, 표준 `aside.notes` 발표자 노트, 근거 링크
- `speaker-script.md`: 단계별 긴 대본, 연출 의도와 클릭 시점, 출처
- `style.css`: 1280×720(16:9) 화면, 타이포그래피·도식·순차 등장 스타일
- `app.js`: Reveal 초기화, 터치 버튼, 발표자 노트 동기화, 단계별 화면 복원
- `vendor/reveal.js`, `vendor/reveal.css`: Reveal.js 5.2.1
- `vendor/LICENSE`: Reveal.js MIT 라이선스

외부 CDN·웹폰트·이미지 요청, 런타임 파일 가져오기, ES 모듈 로딩을 사용하지 않습니다. 외부 근거·앱 링크는 사용자가 누를 때만 접속합니다. 시스템 한글 글꼴을 사용하므로 PC별 글꼴 모양은 다를 수 있습니다.

파일 직접 실행을 위해 별도 발표자 노트 창을 사용합니다. Reveal.js 기본 노트 플러그인 대신 로컬 스크립트로 창을 동기화하며, 다음 슬라이드는 제목으로 표시합니다.
